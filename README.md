# Облік ПК · Агенти захисту

Веб-дашборд обліку комп'ютерів і агентів захисту у підрозділах. Дані читаються з Google-таблиці, статична сторінка без сервера й збірки.

**Можливості:** огляд і статистика (ОС, агент захисту, роки випуску), картки підрозділів, реєстр із пошуком, фільтрами й редагуванням, автоперевірка проблем (дублі IP/MAC, Windows 10, без агента тощо), блоки, які можна перетягувати та розтягувати, збереження макетів, вхід із користувачами та правами, налаштування вкладок.

## Швидкий запуск на GitHub Pages

1. Створіть репозиторій на GitHub і завантажте в нього **весь вміст цієї папки** (`Add file → Upload files`, перетягніть файли й папку `assets`).
2. Відкрийте **Settings → Pages**. У розділі *Build and deployment* виберіть **Deploy from a branch**, гілку `main` і папку `/ (root)`, натисніть **Save**.
3. За 1–2 хвилини сайт з'явиться за адресою `https://ВАШ-ЛОГІН.github.io/НАЗВА-РЕПОЗИТОРІЮ/`.
4. Дозвольте цю адресу для входу через Google (обов'язково, інакше вхід не спрацює):
   - [Google Cloud Console](https://console.cloud.google.com) → **APIs & Services → Credentials** → ваш **OAuth client ID** (Web application);
   - у **Authorized JavaScript origins** додайте `https://ВАШ-ЛОГІН.github.io` (лише домен, без назви репозиторію й без `/` в кінці);
   - збережіть (зміни можуть діяти до кількох хвилин).
5. Відкрийте сайт, увійдіть і в **Налаштування → 🔑 Увійти через Google** увійдіть у Gmail, який має доступ до таблиці.

## Налаштування

Усе основне в `config.js`:

| Параметр | Що це |
|---|---|
| `sheetId` | ID Google-таблиці (між `/d/` і `/edit` у посиланні) |
| `clientId` | OAuth Client ID із Google Cloud |
| `adminHash` | хеш стартового пароля адміністратора (логін `admin`) |

Таблиця читається так: кожен аркуш — окремий підрозділ із колонками «Посада», «Закріплена особа», «Модель ПК», «Інвентарний номер», «ІР адреса», «МАС адреса», ОС Windows/Ubuntu, «Наявність агенту захисту» та ін. Нові аркуші додаються в **Налаштування → Підрозділи**.

Вступну анімацію «рій стрілок» (швидкість, кількість, колір) налаштовують у **Налаштування → Джерело даних**; кнопка **▶ Показати** запускає перегляд.

Стартовий пароль адміністратора змініть одразу: **Налаштування → Мій профіль**. Користувачі, права, вкладки й макети зберігаються в браузері (localStorage) і не синхронізуються між пристроями.

## Локальний запуск

Вхід через Google не працює з `file://`, потрібен локальний сервер:

```bash
python -m http.server 8000
```

і відкрийте `http://localhost:8000`. Додайте `http://localhost:8000` до *Authorized JavaScript origins*.

## Структура

```
index.html        розмітка
config.js         налаштування (таблиця, Client ID, пароль адміна)
assets/style.css  стилі
assets/app.js     уся логіка
.nojekyll         вимикає Jekyll на GitHub Pages
```

Бібліотека XLSX (імпорт файлу) завантажується лише тоді, коли ви її використовуєте.

## Безпека

- Вхід за логіном і паролем та права користувачів працюють **у браузері**, тому це розмежування для зручності, а не захист даних: хто вміє відкрити код сторінки, може його обійти.
- У публічному репозиторії видно `config.js` (Client ID і хеш стартового пароля). Client ID не секрет, але стартовий пароль після публікації змініть.
- Справжній захист даних забезпечує Google: таблицю бачать лише акаунти з доступом, а сайт читає її після входу через Google. Для суворішого контролю використовуйте приватний репозиторій і обмеження доступу до таблиці.

## Якщо щось не працює

| Симптом | Причина |
|---|---|
| `origin_mismatch` / `redirect_uri_mismatch` | адреси сайту немає в *Authorized JavaScript origins* |
| `access_denied` | Gmail не доданий у *Test users* на екрані згоди OAuth |
| `Sheets API 403` | не ввімкнено Google Sheets API або в акаунта немає доступу до таблиці |
| «Сесія Google закінчилась» | токен діє близько години, натисніть «Увійти через Google» ще раз |
| Стара версія після оновлення | оновіть сторінку з очищенням кешу (`Ctrl+F5`) |
